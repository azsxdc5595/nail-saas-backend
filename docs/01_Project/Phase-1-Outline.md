# 第一階段大綱：核心基礎

## 1. 文件目的

整理 Nail SaaS 第一階段的目標、範圍、主要工作流、交付成果及待確認事項，作為後續需求拆解與設計討論的起點。本文件是大綱，不取代正式需求、使用者流程、DDL、API 規格或 ADR。

## 2. 階段目標

建立會員、店家與美甲師可使用的核心基礎能力，讓美甲師能維護基本資料、服務項目及作品貼文，為後續預約流程提供必要資料。

本階段的模組範圍沿用 [Roadmap](Roadmap.md) 定義：Authentication、Shop Management、Manicurist、Portfolio、Service Item。

## 3. 目標使用者與價值

| 使用者 | 第一階段需要完成的事 |
| --- | --- |
| 會員 | 建立並驗證帳號、登入，瀏覽可供探索的作品與服務資訊（瀏覽能力是否列為本階段交付，待確認）。 |
| 美甲師 | 登入後維護個人資料、店家歸屬、服務項目及作品貼文。 |
| 店家管理者 | 建立店家並管理店家資訊、邀請碼及加入流程。 |

## 4. 功能範圍

### 4.1 納入規劃

- 帳號註冊、Email 驗證、登入及 Token 安全機制。
- 建立店家、查詢目前所屬店家、邀請碼及加入店家。
- 美甲師資料查詢與本人資料維護。
- 服務項目的建立、查詢、修改、停用或刪除（操作語意以正式 API 規格為準）。
- 作品貼文建立、查詢、修改、刪除及多圖片 metadata 管理。
- 基本身分驗證、角色／資源所有權檢查及輸入驗證。

### 4.2 暫不納入本大綱承諾

- 預約建立與完整預約生命週期、評價。
- 即時聊天、推播通知、收藏、推薦與進階搜尋。
- 線上付款、電子發票、行動應用程式及營運分析。
- 作品圖片檔案的正式上傳、儲存與讀取流程；目前 Portfolio 規格僅涵蓋圖片 metadata。

以上排除範圍依現有 Project 與 Roadmap 文件整理；若需調整，應先確認產品範圍並同步更新文件。

## 5. 建議工作流

```text
建立並驗證帳號
        ↓
登入
        ↓
建立店家或使用邀請碼加入
        ↓
建立／維護美甲師資料
        ↓
維護服務項目
        ↓
建立作品貼文與圖片 metadata
        ↓
查詢作品及服務資訊
```

此流程是規劃大綱。角色資格、替代路徑、失敗處理及公開瀏覽權限仍須由產品流程文件確認後，才能作為實作依據。

## 6. 預期交付成果

1. 完成並確認本階段需求及範圍。
2. 完成本階段相關 User Flow 與角色／權限規則。
3. 確認 DDL 與逐表設計文件，並處理實體模型不一致。
4. 完成本階段 API Specification，統一路徑、回應格式、錯誤碼及驗證規範。
5. 依核定文件完成後端模組與必要資料存取。
6. 完成可供產品驗收的核心情境及錯誤情境清單。

## 7. 階段完成檢核（草案）

- 使用者可依核定流程註冊、驗證及登入。
- 店家及美甲師資料操作符合核定角色與所有權規則。
- 美甲師可依核定規格管理服務項目與作品貼文；作品可關聯多筆圖片 metadata。
- API、資料表與程式實作一致，並有對應文件。
- 關鍵權限、輸入驗證及交易邊界已完成設計與驗收。
- 未解決的 DDL、API 或產品流程衝突已列明並取得決策。

以上為建議檢核項目，正式驗收條件與驗收責任人待確認。

## 8. 依賴與待確認事項

依目前文件盤點，進入實作或正式驗收前需處理下列事項：

- 確認第一階段是否包含會員公開瀏覽作品／服務，以及對應 API 與公開權限。
- 確認店家、邀請、美甲師角色及加入／重複加入流程；現有邀請 API 文件已有部分規則，但完整流程仍待補齊。
- 確認 `NAIL_POST` 與 `MANICURIST_WORK` 的產品職責及是否並存。
- 依權威 DDL 完成資料表設計文件，確認 Entity 與 DDL 不一致處。
- 補齊本階段 API 契約與錯誤處理規範。
- 確認作品圖片檔案儲存方案及可信 metadata 來源；若留待後續階段，明確定義本階段可交付的圖片能力。
- 依 [TODO](../08_Management/TODO.md) 處理基線、文件與驗證待辦。

## 9. 階段邊界

Reservation 已在 Roadmap 列為第二階段，但 Module Catalog 顯示 Reservation 為 In Design，且近期程式已有相關初始化。這表示規劃與目前實作進度需要校準；本文件不將既有程式視為階段核准依據，也不把 Reservation 納入第一階段範圍。請在確認產品階段基線時一併決定其處理方式。
